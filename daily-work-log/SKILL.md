# 날짜별 누적 업무일지

쌩초가 하루(또는 지정한 날짜) 업무 정리를 요청하면, 프로젝트 기록을 근거로 시간대별 업무일지를 만들어 **누적 파일 하나**에 날짜 섹션으로 추가한다.

## 명령
- "오늘 업무일지 정리해줘" → 오늘 날짜. "11월 26일 업무일지 정리해줘"처럼 날짜를 붙이면 그 날짜.

## 출력 규칙 (가장 중요)
- 누적 파일은 **쌩초 컴퓨터의 `E:\#업무일지\업무일지_누적.html` 한 파일**이고, 모든 프로젝트가 이 파일 하나에 쌓는다. 어느 프로젝트에서 요청받든 같은 파일을 쓴다.
- 작업 순서: 폴더 접근이 없으면 `device_request_folder_access`로 `E:\#업무일지`를 요청(도구가 없으면 connect_device) → `device_stage_files`로 현재 파일을 가져와 수정 → `device_commit_files`로 같은 경로에 덮어쓴다(stage때 mtime을 expectedMtimeMs로). 컴퓨터가 꺼져 있어 못 쓰면 쌩초에게 알리고, 프로젝트 폴더에 임시 본을 만들지 않는다.
- 한 날 여러 프로젝트를 했으면 그 날짜 섹션 안에 합친다: PROJECT 필에 프로젝트들을 나란히 쓰고, 시간대별 카드 태그 앞에 프로젝트명을 붙인다. 다른 프로젝트에서 이미 쓴 같은 날짜 섹션이 있으면 지우지 말고 그 프로젝트 카드는 그대로 두고 이 프로젝트 카드만 시간 순서에 맞게 넣는다. 근무·대기 시간은 두 프로젝트 요청 시각을 합쳐 다시 계산한다.
- 파일 자체 규칙: 파일 안의 CSS·JS(넘김 라이브러리, 메뉴, 소리, 복사 버튼)는 그대로 두고, 새 날짜 섹션 `<section class="day-log" id="d-YYYYMMDD" data-date="YYYY-MM-DD">…</section>`만 `#book` 안 `<!--NEW-DAY ...-->` 주석 바로 아래(최신이 위)에 넣는다. 섹션 안은 `.page` 단위(A4 한 장 = `.page` 하나).
- 상단 메뉴(윗줄 월, 아랫줄 그 달의 일)는 섹션의 data-date로 자동 생성되므로 직접 고치지 않는다.
- 같은 날짜 섹션(`id="d-YYYYMMDD"`)이 이미 있으면 새로 만들지 말고 그 섹션을 교체한다.
- PNG·PDF·날짜별 단독 HTML 등 다른 파일은 만들지 않는다(쌩초가 따로 요청할 때만). 썸네일 추출, 렌더 확인용 스크린샷, 빌드 스크립트는 전부 scratchpad에서만 작업한다. 사용자 기기(로컬 폴더)에도 아무것도 쓰지 않는다.
- 파일이 없으면 마지막 섹션 디자인을 기준으로 새로 만든다.

## 1. 기록 모으기
- `read_project_chat`, `list_threads`(해당 날짜에 활동한 스레드), 각 스레드 `read_thread`로 그날 메시지를 전부 읽는다. 페이지가 남으면 cursor로 끝까지 읽는다.
- 시간은 모두 한국 시간(KST)으로 쓴다.
- 쌩초가 보낸 메시지 시각을 모두 모아 정렬한다.

## 2. 시간 계산
- 근무 시간대 = 첫 요청 ~ 마지막 요청(또는 마지막 결과물) 시각, 총 근무 시간 = 그 차이.
- 대기 = 쌩초 요청 사이 간격이 15분 이상인 구간. 실작업 = 총 근무 − 대기.
- 추정치가 아니라 메시지 시각으로 계산하고, 확인 못 한 구간이 있으면 답장에 밝힌다.

## 3. 업무 항목 만들기
- 시간 순 카드. 같은 시간에 겹친 일은 '병행' 표시.
- 각 카드: 시작·끝 시각, 태그(기획 / 교안 / 차시-클립 번호), 제목, 설명, '결과'(파일·페이지 위치), 썸네일, 상태(완료/진행중).
- **나중에 봐도 알 수 있게** 쓴다: 무엇을, 왜 했고, 결과가 어디 있는지. 고스트샷·UGC·와일드카드처럼 낯선 말은 괄호로 짧게 풀어 쓴다. 개조식 명사형 문장.
- 15분 이상 대기 구간은 카드 사이에 빗금 줄로 넣는다(`.idle`: 시각, 'N분 대기', '요청 없음').
- 섹션 하단: 결과물 위치(파일 경로), 내일 할 일(체크박스), 오늘 정한 규칙(R1…).
- 상태는 실제 파일로 확인한다(예: 영상 mp4가 생성돼 있으면 완료).

## 4. 썸네일
- 그날 만들거나 수정한 이미지·영상을 `/mnt/project-files/` 아래에서 찾는다(`find -newermt`).
- 영상은 ffmpeg로 대표 장면 한 프레임을 뽑아 내용이 보이는 장면인지 확인한다.
- Pillow로 긴 변 420px JPEG(품질 80)로 줄여 base64 data URI로 HTML에 바로 넣는다(파일 하나로 어디서든 열리게).
- 카드당 1~3장, 캡션은 짧게.

## 5. 디자인 (기존 섹션과 동일하게 유지)
- 작성자는 쌩초 개인. 상단 왼쪽은 `Work Log · 쌩초`. 소속 칸은 두지 않는다. '마소캠퍼스' 같은 회사명은 소속이 아니라 그날 진행한 프로젝트로, 필에 `PROJECT 마소캠퍼스 · 힉스필드 MCP 강의 교안`처럼 쓴다(그날 실제 프로젝트명으로).
- 쪽 번호는 상단 오른쪽 `<span class="pgno"><i>PAGE</i><b>01</b><em>/ 02</em></span>`. 2장 이상인 날은 `pgno multi`(검정 바탕·라임 큰 숫자)로 눈에 띄게.
- 하단은 `<div class="foot"></div>` 검정 줄 하나만(종이 맨 아래 5mm). 줄 밑에 글씨를 넣지 않는다. 내용이 줄과 겹치지 않게 카드 단위로 다음 장에 넘긴다.
- 결과물 위치는 행마다 `<button class="cp" data-c="전체경로">복사</button>`. 경로는 `힉스필드\\문서\\…`처럼 힉스필드 폴더부터 전체.
- 넘김: 모서리부터 말리며 넘어가는 효과(page-flip 인라인), 버튼·방향키·손으로 끌기 모두 종이 소리. 소리 끝 '뚝' 소리 없음. 미리보기 창에서 막히는 history.replaceState 등 주소 변경 코드는 쓰지 않는다.
- 상태 도장(완료·진행중)만 Gowun Batang 명조, 나머지는 전부 고딕: Pretendard(본문·제목), JetBrains Mono(시각·숫자).
- 정형화된 결재 서식은 쓰지 않는다. 잡지 표지 느낌: 큰 날짜 `MM.DD` + 라임 배경 요일, 오른쪽에 작성자 쌩초·업무명 필.
- 색: 배경 #f7f6f1, 잉크 #111, 포인트 라임 #d4ff3a. 태그 색: 기획 노랑, 교안 파랑, 4-1 분홍, 4-2 라임, 4-3 보라(새 클립은 비슷한 파스텔로).
- 통계 카드 5개: 근무 시간대(검정), 총 근무 시간, 실작업(라임), 대기(빗금), 완료/전체.
- '하루 흐름' 막대: 검정 = 작업, 빗금 = 대기, 아래에 시 눈금.
- 카드 그리드: 시간 | 내용 | 썸네일 | 상태. 둥근 모서리, 얇은 테두리로 정돈해서 내용이 눈에 잘 들어오게.
- A4 페이지 단위(`.page` 210×297mm)로 나누고, 넘치면 카드 단위로 다음 페이지로 넘긴다. 쪽 표시 `01 / 02` 갱신.
- 기존 섹션의 CSS 클래스(.page .hero .stats .day .card .idle .files .two .box .foot 등)를 그대로 재사용한다.

## 6. 확인
- Playwright로 scratchpad에만 스크린샷을 찍어 각 `.page`의 내용이 footer 위에서 끝나는지, 썸네일이 제대로 나오는지 확인한다.
- 확인용 파일은 project-files에도, 쌩초 컴퓨터에도 남기지 않는다. 컴퓨터에 쓰는 파일은 누적 HTML 하나뿐이다.

## 7. 답장
- 짧게: 근무·실작업·대기 시간, 주요 업무 한 줄, 누적 파일 링크 하나 첨부.
- 교안 문장 규칙(본문 ~다/~요 마침표, 제목 무마침표)은 업무일지 본문이 개조식이라 해당 없음.
