# 영상 스토리보드

모션그래픽, 키네틱 타이포, 인포 애니메이션, 홍보 영상, 릴스·쇼츠, 인트로, 발표용 영상 등 움직이는 결과물을 만들 때 바로 완성 영상을 뽑지 않고 **재생되고 수정할 수 있는 스토리보드**를 먼저 만든다. 설정 화면이나 입력 폼은 만들지 않는다. 재료와 취향은 전부 채팅으로 받고, 스토리보드는 "보고 → 씬마다 고칠 점 적고 → 반영"하는 데만 집중한다.

## 1. 재료는 채팅으로 받는다

사용자가 채팅에 주는 것을 그대로 쓴다.

**만들기 전에 컬러·폰트·레퍼런스·글자 언어를 먼저 같이 정한다.** 스토리보드를 바로 만들지 말고 한 번의 답장으로 제안한다.
- 글자 언어: 영문 위주인지 한글 위주인지 꼭 묻는다.
- 컬러: 주제·레퍼런스에 맞는 팔레트 2~3안(색 이름과 HEX, 어디에 쓰는지).
- 폰트: 상업 무료 폰트 후보 2~3개(이름, 느낌, 제목/본문 중 어디에).
- 레퍼런스: 받은 레퍼런스에서 무엇을 가져올지(배치·폰트 느낌·움직임·색·컷 리듬·전환) 정리. 레퍼런스가 없으면 이런 느낌으로 가겠다고 한 줄로.
사용자가 고르거나 "좋아"라고 하면 그때 스토리보드를 만든다. 사용자가 이미 다 정해 줬으면 확인 한 줄만 하고 바로 만든다.
- 배경 소스(있으면): 영상 mp4, 사진·일러스트, 로고, SVG. 없으면 배경·도형·아이콘·글자를 코드(HTML/CSS/SVG/Canvas)로 직접 그린다. 순수 모션그래픽도 같은 방식.
- 음악·효과음(있으면): 없으면 소리 없이 만들고 전체 설정에 적는다. 음악이 있으면 박자에 맞춘다. 노래(가사)가 있으면 가사를 받아 화면 문구의 기준으로 삼고, 음성 인식(faster-whisper 등, 단어별 시각)으로 가사 타이밍을 잡아 그 시각에 글자가 나오게 한다. 타이밍이 추정값이면 전체 설정에 적는다.
- 레퍼런스: 이미지·영상 파일은 직접 본다. 링크는 열어 보고, 못 열면 만들기 전에 바로 "이 링크는 못 열었어요, 캡처나 파일로 주세요"라고 말한다. 못 본 레퍼런스를 짐작으로 따라 하지 않는다.
- 주제·문구·스타일·폰트·컬러·화면 비율·길이: 말한 대로 따른다. 말하지 않은 것은 레퍼런스와 주제를 보고 정하고, 무엇을 정했는지 전체 설정에 적는다. 비율은 원본 영상을 따르고, 없으면 용도에 맞게(세로 9:16 / 가로 16:9 / 정사각 1:1).
- 주제 한 줄만 있어도 위 컬러·폰트·레퍼런스 제안은 바로 한다(재료가 없다고 멈추지 않는다).

## 2. 분석

- 영상이 있으면: `ffprobe`로 길이·크기, `ffmpeg -i in.mp4 -vf "select='gt(scene,0.3)',showinfo" -f null -`로 컷 시각, 씬마다 대표 프레임 jpg.
- 음악이 있으면: librosa `beat_track`으로 BPM·박자 시각(없으면 onset 에너지로 근사), 분위기가 바뀌는 구간도 찾는다.
- 컷이 없거나 순수 모션그래픽이면 박자·내용 흐름 기준으로 2~4초씩 씬을 나눈다.
- 레퍼런스 영상은 대충 보지 말고 0.25초 간격 프레임으로 뜯어서 크게 본다. 배치뿐 아니라 **질감과 손맛**까지 적는다: 선 굵기와 거칠기, 낙서 종류와 바뀌는 주기, 종이·사진의 낡은 정도, 겹침, 전환 효과(글리치·휙·번쩍임·빛샘), 필름 먼지, 색 보정. 깔끔한 도형으로 흉내 내지 말고 그 거칠기를 그대로 살린다.
- 드롭섀도(그림자 효과)는 쓰지 않는다. 단색·단순 그라데이션 배경도 피하고(ppt처럼 보임) 실사나 질감 있는 배경을 쓴다. 화면 효과(VFX)는 레퍼런스 수준으로 충분히 넣는다.
- 레퍼런스에서 "배치 / 폰트 느낌 / 움직임 / 색 / 컷 리듬 / 전환 방식" 중 무엇을 가져올지 씬별로 정한다. 씬을 템플릿처럼 똑같이 찍지 말고 요청과 레퍼런스대로 씬마다 다르게 짠다.

## 3. 스토리보드 (HTML 아티팩트 한 장)

**왼쪽: 미리보기 플레이어 (스크롤해도 따라옴, 좁은 화면에서는 위로)**
- 정한 비율의 무대에 실제 영상(있으면)과 코드로 그린 그래픽·글자를 시간표대로 움직인다. 음악을 같이 튼다(영상 소리는 작게, 음악이 위).
- 재생 기능은 모두 넣는다:
  - **전체 재생**: [▶ 재생/❚❚ 일시정지], [처음부터].
  - **화면 누르면 재생/일시정지**: 무대를 클릭·탭하면 토글. 스페이스바도 동일.
  - **부분 재생**: 씬 카드마다 [이 씬만 재생] 버튼. 그 씬 시작부터 재생하고 씬 끝에서 자동으로 멈춘다(사용자가 일시정지하거나 다른 곳을 누르면 구간 재생 해제). 타임라인에도 씬 구간 버튼을 두어 같은 동작.
  - **반복**: 부분 재생을 되풀이하는 [반복] 토글.
- 시간 표시와 타임라인 바: 회색 눈금 = 박자(음악이 있을 때), 색 선 = 씬 경계. 바를 누르면 그 시점으로 이동.
- 재생 시계는 영상이 있으면 video.currentTime, 없으면 audio.currentTime, 둘 다 없으면 performance.now() 기반 자체 시계. 모든 움직임은 시간 t의 함수로 그려 어느 지점으로 이동해도 같은 화면이 나오게 한다(CSS transition에 기대지 말 것, 나중에 프레임 단위 렌더에도 그대로 쓴다).

**오른쪽: 수정용 카드**
- 맨 위 "전체 설정": 비율·길이, 음악(곡명·BPM), 폰트(이름과 라이선스), 색, 내가 정한 것, 이번 버전에서 바뀐 점. 아래 전체 수정사항 칸.
- 씬 카드(씬마다): 썸네일(누르면 그 씬으로 이동), 시간 구간, 제목, [이 씬만 재생], 그리고 4줄 — **화면**(무엇이 보이는지) / **글자**(문구와 위치) / **움직임**(몇 초에 무엇이 어떻게, 전환 포함) / **소리**. 그 아래 "씬 N 수정사항" 칸.
- 재생 중인 씬 카드는 테두리로 강조.
- **적용 버튼은 항상 넣는다.** 전체 수정사항 칸 아래 [전체 수정사항만 적용], 씬마다 수정사항 칸 아래 [씬 N 수정사항 적용], 맨 아래 [전체 적용 (적은 것 모두)]. 누르면 그 칸(또는 적은 것 전부)의 수정사항을 `[전체] …`, `[씬 2 2.4–4.9초] …` 형식으로 클립보드에 복사하고, 버튼 옆에 "복사했어요. 채팅에 붙여 넣어 주세요"라고 보여 준다.
  - 커넥터(mcp)로 대화에 직접 보내는 방식은 쓰지 않는다. 모바일에서 "이 아티팩트는 커넥터를 사용합니다 / 불러올 수 없습니다" 창이 뜨고 전송도 안 된다. 아티팩트에 capabilities를 선언하지 않는다.
  - 빈 칸이면 "적은 수정사항이 없어요"라고만 보여 준다. 클립보드가 막혀 있으면 모아 보기 글을 선택해 두고 길게 눌러 복사하라고 안내한다.
- 맨 아래 "수정사항 모아 보기": `[전체] …`, `[씬 2 2.4–4.9초] …` 형식으로 모으고 [전체 적용]과 [수정사항 복사] 버튼. 입력 내용은 localStorage에 저장(try/catch).

데이터는 두 배열로 둔다. 고칠 때 이 두 배열만 바꾸면 되게 한다.
```js
const SC=[{id:1,s:0,e:2.4,thumb:'fr1',title:'…',scene:'…',text:'…',motion:'…',sound:'…'}, …]; // 씬 카드
const EL=[{id:'title',s:0.21,e:2.4,draw:(t,el)=>{/* t를 받아 위치·크기·투명도·블러 계산 */}}, …]; // 글자·도형·이미지 요소
```
- 등장 시각은 가능한 한 박자에 맞춘다.
- 영상과 음악이 둘 다 있으면 **음악을 미리보기 영상 파일에 미리 합쳐서(ffmpeg, 원본 소리는 작게 섞음) video 하나만 재생한다.** audio를 따로 두고 재생 중에 currentTime을 맞추면 모바일에서 소리가 심하게 깨진다. 음악만 있을 때는 audio 하나를 시계로 쓰고 재생 중에는 currentTime을 건드리지 않는다.
- 영상·음악·썸네일은 아티팩트 파일로 함께 올리거나 data URI로 넣는다. 폰에서도 열리게 미리보기 영상은 720폭 이하로 줄인다.
- 폰트는 상업 무료(구글 폰트 등)만. 나눔손글씨(Nanum Pen Script)는 쓰지 않는다.
- 첫 게시 후 링크를 주고 "씬마다 고칠 점을 적고 [적용] 버튼을 누르면 복사되니 채팅에 붙여 넣어 주세요"라고 한 줄로 안내한다.

## 4. 수정 반복 (이 스킬의 핵심)

- 붙여 준 수정사항을 씬별로 읽고 **말한 씬만** 고친다. 다른 씬의 배치·타이밍은 건드리지 않는다.
- `SC`/`EL`만 바꿔 **같은 아티팩트 URL로 다시 게시**한다(새 링크 금지). 제목 옆 버전을 올리고(v2, v3…) 전체 설정의 "이번 버전에서 바뀐 점"에 짧게 적는다.
- 수정사항이 애매하면 가장 그럴듯하게 고친 뒤 "이렇게 읽었어요"라고 한 줄로 말한다. 되묻느라 멈추지 않는다.
- 안 된다고 하지 않는다. 기존 배치에 안 맞는 요청이면 그 씬만 새로 짠다.
- 한 씬만 고쳤을 때는 답장에 "씬 N의 [이 씬만 재생]으로 확인해 보세요"라고 적는다.
- [씬 N 수정사항 적용]으로 온 요청은 그 씬만, [전체 수정사항만 적용]은 전체 항목만, [전체 적용]은 적힌 것 모두를 고친다.

## 5. 영상으로 뽑기

사용자가 "이대로 영상으로 만들어 줘"라고 하면:
- 같은 `SC`/`EL`로 최종 해상도(세로 1080×1920, 가로 1920×1080 등) 렌더. Playwright로 무대만 띄운 페이지를 시간 t마다 멈춰 찍고(30fps), 영상 배경이 있으면 투명 PNG로 찍어 ffmpeg로 원본 위에 합성한 뒤 음악·효과음을 입힌다.
- 원본 mp4와 함께 폰에서 열리는 작은 버전도 만든다.
- 한 씬만 다시 고칠 때는 전체 재렌더 말고 그 씬 구간만 다시 렌더해 이어 붙인다.
- 긴 렌더는 단계가 바뀔 때마다 한 줄씩 진행 상황을 알린다.
- 사용자의 PC에 음악·영상이 있으면 처음부터 PC 쪽에서 렌더한다.
