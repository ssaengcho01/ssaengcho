# zoom-in-screen: 화면 녹화 영상 확대/축소 편집

화면 녹화 영상에서 **꼭 필요한 곳만** 확대하고, 화면을 바꾸는 **진짜 클릭**에만 빨간 라운드 박스를 넣는다.
효과가 들어간 짧은 구간만 다시 렌더하고 나머지는 원본을 그대로 복사해 이어붙여서 빠르게 끝낸다.

## 절대 규칙 (사용자가 직접 정한 기준)

1. **확대는 꼭 필요한 곳에서만.** 무조건 확대하지 않는다. 확대하는 경우는 다음뿐이다.
   - 중요한 버튼 클릭 (그 버튼이 잘 보이게)
   - 프롬프트/글 입력 (입력창 전체가 보이게)
   - 팝업·설정창 (창 전체가 화면 **가운데** 오게)
   - 사용자가 시간대를 지정해 요청한 구간
2. **확대하지 않는 경우**
   - 오프닝, 파트1이 나오기 전 (사용자가 따로 요청한 구간만 예외)
   - 빈 공간을 비추게 되는 경우, 커서가 그냥 가만히 있거나 떠도는 경우
   - 앱 전체 화면을 보여줘야 하는 장면 (예: 설치된 앱이 처음 뜨는 장면, 결과물 전체를 보여주는 장면)
   - 화면이 바뀐 직후 약 3초 (새 화면 전체를 먼저 보여준다. 팝업은 예외)
   - 모션그래픽, 애니메이션, 큰 자막 카드 장면
3. **배율**: 기본 2배. 전체 맥락이 중요하면 1.5배.
   - 프롬프트 입력은 **2배** (1.5배면 입력창이 화면 아래에 걸려 나중에 넣을 하단 자막과 겹친다. 입력창이 자막 자리보다 위에 오게 잡는다)
   - **같은 입력창이면 입력이 잠깐 멈춰도 중간에 축소하지 말고 쭉 확대 유지.**
   - 확대 → 다음 확대 사이가 짧으면(2.5초 미만, 장면 전환 없음) 축소했다 다시 들어가지 말고 바로 이어서 이동.
4. **카메라는 고정.** 커서를 따라 위아래·좌우로 흔들리면 어지럽다. 확대 중에는 화면을 고정하고, 들어가고 나올 때만 부드럽게(약 0.6초) 움직인다. 장면이 바뀌는 순간에 들어가야 하면 이징 없이 바로 확대(hard cut).
5. **빨간 라운드 박스**: 약간 둥근 사각형 빨간 스트로크(두께 5px, 모서리 반경 최대 14px), 살짝 튀어나오듯 등장.
   - **화면을 실제로 바꾸는 중요한 클릭에만.** 커서가 버튼 위에 잠깐 멈춘 것, 글자 드래그 선택, 장면 전환은 클릭이 아니다.
   - 후보마다 **클릭 직전/직후 프레임을 직접 열어 보고**, 클릭 뒤에 화면이 실제로 바뀌었는지, 맥락상 강조할 만한 클릭인지 확인한 뒤에만 남긴다. (예: '답글' 위에 커서가 멈춘 건 박스 대상 아님)

## 작업 순서

### 0. 준비
- 영상 폴더와 원본 파일을 확인한다. 원본은 절대 덮어쓰지 않고 `원본이름_줌적용.mp4` 같은 새 파일로 저장한다.
- 필요 도구: `ffmpeg`, `ffprobe`, Python 3 + `numpy`, `opencv-python`.
- 작업 파일은 영상 폴더 옆 `_claude_tmp/autozoom/` 같은 임시 폴더에 둔다.
- 이 단계에서 쓰는 스크립트 4개(`detect_cursor.py`, `plan_zoom.py`, `render_zoom.py`, `splice_render.py`)가 스킬 폴더의 `scripts/`에 없으면, 아래 각 단계 설명대로 Python(OpenCV, numpy)과 ffmpeg로 직접 만들어 작업 폴더에 둔다.

### 1. 커서 위치 추출 (`detect_cursor.py`)
커서 좌표 로그가 없으면 화면에서 커서를 색으로 찾는다. 커서를 눈에 띄는 색(예: 분홍색)으로 바꿔 녹화하면 잘 잡힌다.
```
python detect_cursor.py "원본.mp4" WORK/cursor.json --fps 10
```
- 결과: 10fps마다 커서 후보 좌표, 프레임 변화량(`d`, 장면 전환 감지에 씀).
- 커서 색이 다르면 `--rgb-min/--rgb-max`로 범위를 바꾼다. 먼저 프레임 하나를 뽑아 커서 색을 확인할 것.

### 2. 파트1 시작 지점 찾기
오프닝·인트로가 끝나고 실제 내용(파트1)이 시작하는 시간을 프레임을 보고 찾는다. 이 시간 이전은 확대하지 않는다 (`--no-zoom-before`).

### 3. 확대 구간·클릭 후보 계산 (`plan_zoom.py`)
```
python plan_zoom.py "원본.mp4" WORK --t0 0 --dur 영상길이 --no-zoom-before 33.5 [--exclude 152.3,187.0] [--manual WORK/manual.json]
```
- 클릭 후보: 커서가 멈춘 뒤 커서 주변 화면이 바뀐 곳 → 버튼 영역을 찾아 박스 좌표 생성.
- 입력 구간: 커서는 가만있고 가로로 긴 영역에서 글자가 생기는 곳 → 입력창 테두리까지 넓혀 2배.
- 팝업: 어두운 배경 위 흰 창 → 창 전체를 가운데로.
- 장면 전환 후 3초 대기, 같은 입력창 병합, 짧은 간격 연결, 배율 자동 선택(2배 / 1.5배).
- 결과는 `WORK/plan.json`. 출력 로그로 클릭·구간 목록을 확인한다.
- **자동 결과는 후보일 뿐이다.** 다음 단계에서 반드시 사람 눈으로(프레임 이미지로) 검토한다.
- 사용자가 직접 지정한 구간은 `manual.json`에 넣는다 (자동 구간보다 우선):
  ```json
  [{"a": 78.0, "b": 104.0, "z": 2.0, "r": [990, 946, 1837, 1010]},
   {"a": 24.1, "b": 28.0, "z": 2.0, "r": [1040, 760, 1890, 1000], "hard": true}]
  ```
  `a,b`=원본 기준 초, `z`=배율, `r`=보여줄 영역 [x0,y0,x1,y1] (1920x1080 기준), `hard`=장면 전환 순간 바로 확대.
- 잘못 잡힌 클릭은 `--exclude 초,초`로 뺀다.

### 4. 클릭 후보 검증 (필수)
각 클릭 후보 시간 t에 대해 `t-0.3`초와 `t+0.6`초 프레임을 뽑아 직접 본다.
```
ffmpeg -ss T -i 원본.mp4 -frames:v 1 WORK/chk_T.jpg
```
화면이 실제로 바뀌지 않았거나, 강조할 의미가 없는 클릭(답글 hover, 드래그 선택, 장면 전환 오인)은 `--exclude`로 빼고 3단계를 다시 돌린다.

### 5. 정지 화면 시안 먼저 보여주기 (렌더 전에!)
```
python render_zoom.py "원본.mp4" WORK WORK/still stills:45.2,48.0,86.5
```
왼쪽 원본 / 오른쪽 적용 화면을 나란히 붙인 jpg가 나온다. 확대 구간마다 1장씩 사용자에게 보여주고 확인받은 뒤에 렌더한다.
피드백이 오면 규칙을 고친 뒤 **정지 화면으로 다시 확인**하고, 전체 렌더는 한 번만 건다.
가능하면 시안 페이지(아티팩트)로 영상·전후 비교·타임라인을 한 페이지에 묶어 보여준다 (페이지용 영상은 720p/저음질로 줄였다는 점과 실제 파일은 원본 화질·음질이라는 점을 말해 줄 것).

### 6. 빠른 렌더: 효과 구간만 렌더 + 나머지는 원본 복사 (`splice_render.py`)
```
python splice_render.py "원본.mp4" WORK "원본_줌적용.mp4"
```
- `plan.json`의 확대 구간·빨간 박스 구간을 원본 키프레임 경계에 맞춰 넓힌 뒤, 그 구간만 다시 인코딩한다.
- 나머지 구간은 `-c copy`로 화질 손실 없이 복사한다.
- 오디오는 원본 전체를 그대로 복사해 붙인다 (재인코딩 없음 → 음질 그대로, 싱크 그대로).
- 길이는 원본과 같아야 한다. 끝나면 `ffprobe`로 길이를 확인하고, 효과 구간 몇 곳의 프레임을 뽑아 박스·확대가 제자리에 나오는지 확인한다.

### 7. 나눠서 전달
- 사용자가 확인할 땐 **확대·빨간 박스 들어간 구간만 잘라 이어붙인 확인용 짧은 영상**을 먼저 줄 수 있다.
- 전체 영상은 **앞부분 / 뒷부분 두 번에 나눠** 전달한다. 앞부분을 확정받은 다음, 같은 기준으로 뒷부분을 작업한다.
  ```
  ffmpeg -i 원본_줌적용.mp4 -t 205 -c copy "원본_줌적용_앞부분(0000-0325).mp4"
  ffmpeg -ss 205 -i 원본_줌적용.mp4 -c copy "원본_줌적용_뒷부분(0325-0651).mp4"
  ```
  (자르는 지점은 키프레임 위치로. 재인코딩 없이 복사만)
- 둘 다 확정되면 합친 완성본 경로를 알려준다.

## 소통 규칙
- 진행이 길어지면 지금 단계와 남은 시간을 짧게 알린다. 렌더 예상 시간을 미리 말한다.
- 피드백마다 전체를 처음부터 다시 렌더하지 않는다. 정지 화면 → 확정 → 효과 구간만 렌더.
- 결과를 줄 때는 확대한 곳 목록(시간, 배율, 이유)과 뺀 클릭 후보(이유)를 함께 말한다.
- 사용자가 지적한 시간대는 모두 다시 확인했다고 근거와 함께 알린다.
